# 既存機能・UIの調査と再利用

このサイトの機能・UIの追加や修正について、案を提示するとき、設計するとき、または実装するときに適用する。案の提示だけの場合も、作業を始める前にこの方針を読む。

- 提案・設計・実装を始める前に、他のページに同じ用途や近い振る舞いの機能・UIがないか調べる。画面の表示名や操作内容、関連するコード名を手掛かりに、実装と既存の仕様・テンプレートを検索する。
- 見つかった候補は、該当箇所と利用している共通部品・処理を読んで確認する。名前や検索結果だけで、再利用できると判断しない。
- 要件に合う既存の部品・処理・定義・スタイルを優先して使う。調整が必要な場合は、既存の利用箇所への影響を確認し、今回の変更に必要な範囲で拡張・共通化する。
- 再利用するときは、部品や処理だけでなく、見た目・表示項目・初期設定・操作方法も確認し、今回の要件に合う範囲で既存実装に揃える。既存の表示や機能を省略・無効化したり、初期値や操作方法を変えたりする場合は、依頼内容に照らして必要性を判断し、理由を簡潔に示す。
- 同じ役割の実装をページごとに作り直さない。再利用のために、依頼と無関係な一括移行や大規模な改修を行わない。
- 提案・設計では、参考にしたページや部品、再利用する部分、追加・変更が必要な部分を簡潔に示す。実装後も、実際に再利用したものと変更点を伝える。
- 適切な候補が見つからない場合や、既存実装が要件に合わない場合は、その旨と新規作成が必要な理由を簡潔に示す。
