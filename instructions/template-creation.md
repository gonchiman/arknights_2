# テンプレート作成の共通手順

このプロジェクトのUI・配色・グラフなどについて、ユーザーから「テンプレ化」「テンプレートとして保存」「今後の標準にする」と依頼されたとき、および既存テンプレートを更新するときに適用する。個別の指示がある場合は、その対象範囲や保存形式を優先する。

## 1. 基準と適用範囲を整理する

- 会話で採用された案と現在の実装を確認し、何を再利用するかを定める。既存の同じ用途のテンプレートがあれば、それを更新する。
- 対象と対象外、固定する仕様、利用ごとに変更できる値を区別する。例として、配置や色の意味は固定し、タイトル・データ・条件などは入力として扱う。
- テンプレート化を理由に、採用済みの見た目、色の意味、計算、動作を変更しない。会話と実装が食い違い、結果に影響する基準を判断できない場合は、その点を確認する。

## 2. 仕様・再利用する部品・見本を保存する

原則として次の構成にそろえる。パスはプロジェクトルートからの配置例。

| 成果物 | 保存先と役割 |
| --- | --- |
| 仕様書 | `docs/<テーマ名>/README.md`。適用範囲、固定仕様、可変部分、使い方、確認方法をまとめる |
| 再利用する部品・定義 | 既存の構成に合わせて `src/components/`、`src/lib/` などに置く。利用側から参照する実装や定数の共通の定義元とする |
| 見本 | `docs/<テーマ名>/examples/`。対象に合ったPNG・SVG・入力例・出力例などを保存する |
| 読み込みの入口 | プロジェクトの `AGENTS.md`。そのテンプレートを使う作業と仕様書へのリンクを登録する |

- コードで共有できる部分は既存の共通部品・定義を優先して使い、必要な共通部分だけを切り出す。ページごとに同じ定義をコピーしない。
- コードを必要としない対象では、再利用するひな形・設定・手順を保存する。用途に合わない実装を新設しない。
- 見本の文字や数値は例として扱い、今後の出力に固定しない。見本が採用済みデザインの参考なのか、現在の定義から再生成する確認用なのかを明記する。
- 既存の採用済み見本は、その用途を明記して利用できる。実装の確認用として画像やUIの見本を新しく作る場合は、実装・実際の出力から作る。再生成する見本には、生成方法と更新時の手順も残す。
- 保存先やリンクの管理には [指示ファイルの管理方針](agents-writing.md) を適用し、別PCでもプロジェクト内のファイルだけで参照できるようにする。

## 3. 仕様書の項目をそろえる

新しい仕様書には次の項目を含める。既存の仕様書を更新する場合は、内容が既にある項目を重複させず、不足する情報を補う。

1. **用途と適用範囲**：いつ使うか、対象外は何か。
2. **保存場所と役割**：共通部品・定義・見本への相対リンクと役割。
3. **固定仕様と可変部分**：維持する配置や意味、変更できる入力と既定値。コードが定義元の値は参照先を示し、仕様書に二重管理しない。
4. **使い方**：最小限の利用例と必要な入力。コード例の仮置き名は、その旨を示す。
5. **見本と更新方法**：見本の用途、確認するポイント、再生成方法がある場合はその手順。
6. **適用状況**：現在の適用済みの箇所と、未移行の既存箇所。
7. **変更時の確認**：維持すべき条件と、対象に合った検証方法。

## 4. 今後の作業から参照できるようにする

- `AGENTS.md` に、完成した仕様書への参照を追加・更新する。読む条件は「グラフの画像出力を作成・変更するとき」のように具体的にし、ユーザーが再度「テンプレートを使って」と言わなくても該当作業から判断できるようにする。
- `AGENTS.md` に仕様の本文を複製しない。関連する既存テンプレートがある場合は、役割の分担と併用する条件を仕様書に記載する。
- 既存箇所への適用は依頼された範囲で行う。テンプレートを保存したことと、既存箇所へ適用したことを区別する。

## 5. 検証して反映状況を報告する

- 仕様・共通定義・見本が一致していること、参照先が実在し、読み込み条件が適切なことを確認する。
- 見た目を扱う場合は実際に描画した結果を確認し、画像保存を扱う場合は生成した画像も確認する。対象に応じて長い文字列、データ量、サイズや比率の違いを確認する。
- 計算や共通ロジックを変更した場合は、その振る舞いに合ったテストを行う。アプリのコードを変更した場合は必要なビルドも確認する。文書だけの変更では参照・内容の確認を行う。
- 完了報告には、仕様書・再利用する部品・見本の場所、AGENTS.mdへの登録、検証結果、適用範囲を簡潔に示す。mainへの取り込みとGitHubへのpushが済んでいるかも区別して伝える。
