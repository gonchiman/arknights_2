# アプリの階層とページの分け方

新しい機能・タブ・ページを提案、設計、実装するときと、既存機能の移植やナビゲーションの再編時に適用する。

## ページの単位

機能の置き場所を決める前に、「このページで何を知りたいか」を一文にする。データベースや作成ツールでは「ここで何をしたいか」で考える。設計上の判断に使う一文を、画面の説明文として追加する必要はない。

| 利用者の目的 | 配置 |
| --- | --- |
| 同じ結果を別の形式で読みたい | 同じページで表示形式を切り替える。例として、出現敵での属性別の優勢率の表とグラフがある。 |
| 一つの問いに答えるため、条件を保って複数の内訳を見比べたい | 同じページにまとめる。並べて比較する結果は一緒に表示し、切り替えて比較する結果にはタブを使える。 |
| それだけでも開く目的がある別の問いを調べたい | 別ページにして関連する場所からリンクする。たとえば「出現敵にどちらの属性が有利か」と「どんな敵が何回出たか」は別々に調べられる。 |

集計版・絞り込み・計算処理などを共有する機能でも、ページを分ける判断は利用目的に基づく。共通処理や操作部品はページをまたいで再利用する。

## 入口とページ間の関係

- **ラボ**は一つの研究テーマの入口とする。ホームとサイドバーからラボを開き、ラボのトップに研究テーマと利用できるページ名を縦に並べる。結果を見て次に調べられるページは、字下げと枝線で関係を示す。同じページを別の分析からも参照するときは、同じ行き先へリンクする。
- **汎用機能**は、複数のテーマで使う敵データベースなどを想定し、特定のラボから独立して配置する。研究に役立つ場合は、該当するラボからもリンクする。
- **保管庫**は、普段の導線から外した既存ページを引き続き開き、過去の結果や実装を参照する場所とする。ホームとサイドバーには保管庫への入口を置き、収録ページは保管庫で選べるようにする。

## 既存ページの段階移植

複数の目的を持つ既存ページは、今回移す機能を選び、その問いと配置先を決めてから移植する。移植した機能を配置先から開けることと、残りの機能を保管庫の元ページから既存URLで利用できることを確認する。
