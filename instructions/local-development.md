# 機能開発の作業フォルダと開発サーバー

機能開発でファイルを編集する前、開発サーバーの起動・再起動や配信元を確認するとき、`main` の作業フォルダを切り替えるときに適用する。

## 機能開発を始める前

- 最初の編集前に `git worktree list` で `main` の作業フォルダを確認し、機能開発には別の作業フォルダを用意する。そのフォルダで編集と確認を行う。サーバーを起動しない機能開発にも、この作業フォルダの分離は適用する。

## 機能確認用サーバー

- 機能開発の続きで、対象の指定なしに「起動」と依頼されたときは、機能確認用サーバーを起動する。起動前に `git worktree list` と起動元での `git branch --show-current` で、対象の機能開発用フォルダが起動元になっていることを確認する。
- 機能開発用フォルダから、5173番以外の空きポートで起動する。たとえば5174番が空いていれば、`npm run dev -- --host localhost --port 5174 --strictPort` を実行する。

## `main` 用サーバー

- `main` は利用者が普段使うクローン先で開き、そのフォルダから `localhost:5173` を起動する。Windows での配置例は `%USERPROFILE%\Documents\arknights_2`。端末ごとに利用者が指定したクローン先を使う。
- 起動前に `git worktree list` と起動元での `git branch --show-current` で、クローン先が `main` になっていることを確認する。`main` が別の作業フォルダで開かれている場合は、未コミットの変更を確認し、利用者が指定したクローン先で `main` を開けるようにする。
- `main` 用のサーバーはクローン先で `npm run dev -- --host localhost --port 5173 --strictPort` を実行する。5173番が使用中の場合は、動作中のサーバーの配信元を確認する。
