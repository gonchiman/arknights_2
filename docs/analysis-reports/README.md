# 分析レポートの標準

## 1. 用途と適用範囲

このプロジェクトのグラフ・統計などの分析出力を、文書のレポートとして作成・修正するときに使う。図と読み取り結果を1ページ目にまとめ、根拠となる条件や定義を必要に応じて後続ページへ分ける。

通常のチャットでの説明、アプリ画面のUI、グラフ自体の設計、他プロジェクトのレポートには一律に適用しない。ページ構成・形式・保存先などに今回の依頼で指定があれば、その指定を優先する。個人用スキルのインストールを前提とせず、この仕様とひな形をプロジェクト内の参照元にする。

## 3. 固定仕様と可変部分

### ページの構成

1ページ目は、次の順で読めるようにする。

1. 対象と目的が分かるタイトル、主要な集計条件。
2. 分析から得られる結論。
3. 元の図と短い図題。
4. 図から読み取れる特徴と、その根拠となる数値。
5. 尺度・単位・分母が整合する場合の相対比較。

2ページ目は、必要な場合に集計対象・重み・有効数・欠損数・定義・限界・出典をまとめる。読み取りに必要な条件は1ページ目にも短く記載する。補足が少ない場合は1ページで完結させ、空白の2ページ目を設けない。内容量や依頼に応じて後続ページを使い、2ページへ収めるために図や文字を読みにくく縮小しない。

### 数値と解釈

- 図に表示された事実、数値から算出した派生指標、その解釈を区別して書く。派生指標は式・分母・単位を確認し、元図にある値のように扱わない。
- 集計版、対象範囲、フィルター、集計単位、重み、欠損の扱いを今回の出力に合わせる。画像から確認できない条件は、同じ出力のデータや実装で確認し、確認できない事項を推定で埋めない。
- 敵の種類数、登場マップ数、出現回数は区別する。点の個数や棒の見た目から集計重み・度数を復元しない。
- 単位や数値軸の異なる図の長さを直接比較しない。正規化する場合は変換と分母を明示し、分母が0などで定義できない場合は値を作らない。
- 中央値による正規化や特定の統計量を、すべての分析へ適用しない。分布の比較だけから相関、換算上の等価性、ダメージ上の優劣まで結論を広げない。

### 図と入力

図の数値、色の意味、縦横比を保持する。文書内では縦横比を保って配置し、値や目盛りを作り直したり、横方向・縦方向だけを伸縮したりしない。グラフ画像を作成・変更する場合は[既存の画像出力仕様](../chart-image/README.md)を併用し、この文書で画像仕様を再定義しない。

タイトル、図、対象データ、集計条件、結論、使用する指標、文書形式、ページ数、保存先は可変入力とする。見本の対象・集計版・数値・作成日・Google Driveフォルダーを、今後の既定値へ固定しない。

## 4. 使い方

1. 今回の目的、入力図、対応する集計データ、指定された出力形式と保存先を確認する。[構成のひな形](report-outline.md)の必要な項目を埋める。
2. 事実・派生指標・解釈の根拠を確認し、結論と図の読み取りを先に書く。対象や条件を変更した場合は、本文・図・図題・表・出典も今回の内容へ更新する。
3. Googleドキュメントが指定された場合は、参照文書のネイティブコピーが利用できれば、原本からコピーを作って編集する。保存先は今回指定されたフォルダーのIDまたはURLを入力として扱う。別の依頼への固定の保存先にしない。Wordなど別の形式が指定された場合は、その形式で作成する。
4. コピーが利用できずローカルDOCXを経由する場合は、利用可能な文書作成・Google Driveのスキルと接続機能の手順に従う。DOCXの作成、Google Docs向けタイトルのサニタイズ、描画確認、ネイティブGoogleドキュメントへの取り込みを行う。原本や参照文書を変更しない。
5. ローカル文書を作成・経由した場合は、その文書の全ページを描画して確認する。Googleドキュメントが最終成果物の場合は、コピー・取り込み・編集の後に、最終GoogleドキュメントからPDFを出力して全ページを描画し、再確認する。変換前の見た目だけで完了としない。
6. 最終文書の形式、内容、保存先を確認して渡す。参照文書の共有設定を変更せず、新規文書でも依頼された範囲を超えて共有や通知を行わない。

保存先の指定や共有に関する権限は、その依頼と接続機能の条件に従う。この標準自体は、外部への保存、原本の変更、共有範囲の拡大を新たに許可するものではない。

## 5. 見本と更新方法

採用した見本は、集計v12・メインストーリー・出現回数の防御力と術耐性を扱ったレポートである。ページ画像は最終ネイティブGoogleドキュメントのPDFから描画した実出力であり、構成・配置の参考として保存する。数値の再計算テストや、すべてのレポートを同じ図にするための入力ではない。

見本を更新する場合は、承認された文書のコピーで改訂し、最終GoogleドキュメントからPDFを出力して全ページを描画する。1ページ目の分析と図、2ページ目を使う場合の根拠・定義・限界が読めることを確認し、対応するローカル文書・入力図・ページ画像を揃えて保存する。配置の変更と数値・対象の変更を区別し、古い見本を無関係な依頼の一部として一括更新しない。

## 6. 適用状況

適用済みの見本は、上記の防御力・術耐性の分析レポートである。今後このプロジェクトの分析出力からレポートを作成・修正するときは、ルートの`AGENTS.md`からこの仕様を参照する。

既存の統計ガイド、表記ガイド、アプリ画面、グラフ出力には一括適用していない。個人用の文書テンプレートスキルとは別に、プロジェクト内で構成と確認手順を共有する。

## 7. 変更時の確認

- `AGENTS.md`の読み込み条件が分析出力のレポート作成・修正に限定され、関連リンクが実在し、個人の絶対パスや一時フォルダーに依存していないこと。
- 図・本文・派生指標・集計条件が一致し、見本の固定値や過去の対象が残っていないこと。重みや欠損の扱いが確認できること。
- 1ページ目で結論・図・分析・有効な比較を読めること。補足ページがある場合は対象・定義・限界・出典を確認でき、不要な空白ページがないこと。
- 図の縦横比、色、値、目盛り、文字を保ち、文字の欠け・重なり・表の分割・図題の取り残しがないこと。長いタイトルや条件でも読めること。
- ローカル文書を作成・経由した場合はその全ページを、Googleドキュメントを納品する場合は最終GoogleドキュメントのPDF全ページも確認したこと。フォント代替や表の折り返しによる改頁の変化を見落としていないこと。
- 最終文書が依頼された形式とフォルダーにあり、参照原本と共有設定を変更していないこと。プロジェクト仕様だけの変更では、リンク・内容・共通ルールの整合性を確認し、アプリのビルドを追加の完了条件にしない。
