# MOD共通配色

このプロジェクトで、MODの種類や潜在を色で区別する表示を新規作成・修正するときに適用する。グラフの系列、凡例、表の色見本、画像出力で同じ対応を使う。ダメージ内訳など、MOD以外の意味を持つ色分けは対象外とする。

## 定義と見本

- [moduleColors.ts](../../src/lib/moduleColors.ts) を色値と潜在ごとの濃淡の唯一の定義元とする。ページごとにパレットや濃淡の計算を複製しない。
- [palette.svg](examples/palette.svg) は、共通コードから生成した基準色・潜在別の見本と、比較条件による使い分けの確認用。実際の色値もこの見本で確認する。
- [generateModuleColorExample.mjs](../../scripts/generateModuleColorExample.mjs) が見本を生成する。色を変更したら、リポジトリルートで次のコマンドを実行して見本も更新する。

```sh
npm run generate:module-colors
```

![MODの基準色と潜在1〜6の色見本](examples/palette.svg)

## 色の意味

MODの種類で基準色を決める。未装備は灰色、MOD-Xは青、MOD-Yは橙、MOD-Δは紫、MOD-αは緑、MOD-βは赤系とし、不明な種類には専用の色を使う。基準色と濃淡の混合係数は共通コードの `MODULE_BASE_COLORS` と `MODULE_POTENTIAL_SHADES` を定義元とする。

比較する系列の色は `getModuleComparisonColors` に全系列をまとめて渡して決める。

- **同じ潜在だけで比較する場合は基準色を使う。** 潜在1同士でも6同士でも、MODの種類が同じなら同じ基準色となる。系列が1つの場合も基準色とする。
- **異なる潜在を比較する場合は潜在ごとの濃淡を使う。** 指定された潜在を正規化し、異なる値が2つ以上あれば、潜在1から6へ向かって明るい色から暗い色にする。
- 潜在を省略した系列は潜在の種類数に数えず、どちらの比較モードでも基準色を使う。全系列で省略した場合も基準色となる。
- 指定された潜在が1〜6以外の値、小数、`NaN`、無限大の場合は、種類数の判定と色の生成の両方で潜在1として扱う。アプリ内の潜在が0始まりなら、呼び出す前に1〜6へ変換する。
- 同じ比較モードの中では、MODのレベル、系列の追加・削除、表示順や並べ替えで色を変えない。同じ種類と潜在には同じ色を使う。系列の追加・削除によって「同じ潜在だけ」と「異なる潜在」の比較が切り替わる場合は、基準色と濃淡が切り替わる。
- 同色の系列を区別する必要がある場合は、線種、マーカー、ラベルを補助に使う。色だけに識別を任せない。
- 画面、凡例、保存ダイアログのプレビュー、実際のPNGでは同じ比較系列と計算済み条件を使い、同じ色を渡す。比較を各MODや各系列に分けて判定しない。

単独の色見本や潜在別パレットを作るときは `getModuleColor` を使う。潜在を省略すると基準色を返し、指定すると比較条件にかかわらずその潜在の濃淡を返す。この低水準APIの動作は変えない。濃淡は各RGB成分を白または黒へ混ぜ、整数に丸める。

## 種類の表記と未装備

`getModuleColorKey` は種類をNFKCで正規化し、前後の空白を除去して大文字化する。種類のコードを渡し、`MOD-X` などの表示ラベルや名前全体は渡さない。

| 入力 | 共通キー |
| --- | --- |
| `null` | `none`（未装備） |
| `X`、`x`、全角の同表記 | `X` |
| `Y`、`y`、全角の同表記 | `Y` |
| `D`、`d`、`Δ`、`δ`、`∆` | `D` |
| `A`、`a`、`α`、`Α` | `A` |
| `B`、`b`、`β`、`Β` | `B` |
| `undefined`、空文字、空白のみ、その他の未知の種類 | `unknown`（不明） |

未装備を示す値は `null` だけとする。取得できなかった種類や未知の文字列を `null` へ置き換えない。共通キーは判定の結果であり、`none` という文字列を入力して未装備を表すことはできない。

## 使い方

```ts
import { getModuleComparisonColors, getModuleColor, getModuleColorKey } from '../lib/moduleColors'

// 比較グラフと凡例では全系列を渡す。結果は入力と同じ順序。
const comparisonColors = getModuleComparisonColors([
  { moduleType: null, potential: 1 },
  { moduleType: 'X', potential: 1 },
  { moduleType: 'Y', potential: 1 },
]) // 同じ潜在なので、灰・青・橙の基準色。

const potentialColors = getModuleComparisonColors([
  { moduleType: 'X', potential: 1 },
  { moduleType: 'X', potential: 6 },
]) // 異なる潜在なので、明るい青・暗い青。

// MODの種類だけを表す見本。
const baseColor = getModuleColor('X')

// 潜在別パレットなど、指定した濃淡そのものを示す見本。
const potentialSwatch = getModuleColor('Δ', 3)

// 未装備と不明な種類を別の状態として扱う。
const unequippedColor = getModuleColor(null, 1)
const unknownColor = getModuleColor(undefined, 1)
const moduleKey = getModuleColorKey('α') // 'A'
```

上の変数名は利用例。入力が実データのオブジェクトの場合は、未装備かどうかを先に判定し、装備中ならそのMODの種類コードを渡す。MODレベルや系列番号は色の入力にしない。利用側で別の色変換を加えず、返された色を線、凡例、表の見本にそのまま使う。

MOD別のグラフ画像を作成・変更するときは、[グラフ画像出力のテンプレート](../chart-image/README.md)も読む。画像の配置・サイズはそちらの仕様で決め、MODの色はこの共通関数で決める。

## 適用状況

- GG「ターゲット切替2」では、比較系列に応じた基準色・濃淡の使い分けを画面とPNGに適用する。
- GG「性能分析」のパネル3「グラフ表示」は、折れ線グラフ、集合棒グラフ、単一の術耐性の棒グラフ（縦・横、全デザイン）で、比較系列に応じた基準色・濃淡の使い分けを画面とPNGに適用する。凡例・線の端の系列ラベルに使う色見本も同じ系列色を使う。総ダメージ・差分・基準比・増減率のすべてが対象。
- ダメージ内訳の積み上げ色は対象外。ほかの既存ページは、この仕様を追加しただけでは一括変更されない。今後、該当する表示を新規作成・修正するときにこの規則へ合わせる。

## 変更時の確認

- 同じ潜在だけの比較では、潜在1から6のいずれでも基準色になることを確認する。
- 異なる潜在を比較する場合だけ濃淡に切り替わり、同じ比較モード内では系列順やMODレベルを変えても同じ種類・潜在が同じ色になることを確認する。
- 潜在を省略した系列は種類数に含めず基準色となり、不正な潜在は潜在1として判定・描画されることを確認する。
- 未装備、既知の種類、表記揺れ、不明な種類が意図した区分になることを確認する。
- 画面と実際に保存したPNGで、線と凡例の色が一致することを確認する。
- 共通コードの色、濃淡、比較モードの判定を変更した場合は、見本を再生成して全種類・全潜在と比較の使い分けを確認する。生成済みSVGを手作業で修正しない。
