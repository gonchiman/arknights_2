# 分岐出現の監査とV3の判定

V2で `branch-spawn` によって集計対象外だった349マップを母集団として、分岐・呼出元候補・出現対象・環境ごとに分類する。マップ単体を名前で許可する方式は使わず、確認した仕組みとデータの条件が一致するときに共通の判定を適用する。

監査の全件記録は [v3.json](./v3.json)。元データの版は `60e3aaf434919fbca931024a59d51088e810a9d3` に固定している。349マップには1,029個の出現分岐と2,198個のSPAWN指定がある。同じ表示コードでも標準・厄難のlevelIdが異なれば別マップとして数える。

## 今回の結果

349マップのうち70マップをV3で集計可能にした。前のV3で対応していた12マップを含み、今回の追加は58マップ。残る279マップは保留で、220マップは分岐だけが未解決、59マップはほかの未対応条件も持つ。

| 集計対象 | 更新前のV3 | 更新後のV3 | 増加 |
| --- | ---: | ---: | ---: |
| 全体 | 1,396 | 1,454 | 58 |
| メインテーマ | 411 | 439 | 28 |
| イベント | 950 | 980 | 30 |
| 物資調達・SoC | 35 | 35 | 0 |

V2比では70マップ増加。物語環境と「その他」の除外方針は維持する。集計対象外690マップ、データ未取得197マップ、収録総数2,341マップとなった。

新たに集計可能になった58マップの内訳は、非敵の分岐44、必須の使徒出現12、隣接配置での任意出現2。例として11-7は、通常波50体に必須の使徒1体を加えて51体となる。

## 判定する仕組み

| 仕組み | V3の扱い | 実装 |
| --- | --- | --- |
| 未起動のパワードスーツ | 起動を避ける条件で追加出現を除外。通常波にある同じ敵は残す | [optionalEnemyBranchPolicy](../../scripts/lib/optionalEnemyBranchPolicy.mjs) |
| 隣接配置で起動する「盾と壁」 | 隣接4マスに配置しない条件で追加出現を除外 | [deploymentEnemyBranchPolicy](../../scripts/lib/deploymentEnemyBranchPolicy.mjs) |
| 渇欲の枯枝から出る使徒 | 配置された枯枝ごとに必ず出現する使徒を加算。難易度で装置が無効なら0体 | [mandatoryEnemyBranchPolicy](../../scripts/lib/mandatoryEnemyBranchPolicy.mjs) |
| 味方・中立・環境オブジェクト | 確認済みの役割に限り、分岐を敵の出現集計から除外 | [nonEnemyBranchPolicy](../../scripts/lib/nonEnemyBranchPolicy.mjs)、[enemyUnitRoles](../../scripts/lib/enemyUnitRoles.mjs) |

分岐の判定根拠はマップごとの `omittedBranchSpawns` / `countedBranchSpawns` に保存し、マップ詳細のデータ情報から参照できる。ランダム選択、未知の設定、敵の置き換え、未知の呼出元などが残るマップは、部分的な判定結果だけで集計可能にはしない。

通常波にも登場する確認済みの非敵については、マップの実出現表示と登場マップ数を維持し、ヒストグラムの「出現回数」への寄与だけを除外する。記録は `enemy-histogram-counts.json` の `diagnostics.excludedNonEnemySpawns` に残す。役割を変える可能性のある未確認の上書きは除外せず、`unverifiedNonEnemySpawns` に記録する。元データの版が異なる場合にも、確認済みとみなして除外しない。

## 保留する仕組み

| 主な群 | 母集団内のマップ数 | 保留理由 |
| --- | ---: | --- |
| `sgkill` を参照する群 | 34 | `trap_092_vgctrl` の時間経過によるSP回復と、ループする分岐呼出しがある。未発動でクリアできるか、呼出回数を確定できない |
| `cnnon` を参照する群 | 14 | 敵を運ぶ砲台の分岐が追加召喚か輸送ルート指定か、実行元の結び付けを確認しきれていない |
| `dhdcr` を参照する群 | 11 | 汚染での起動とHP減少による召喚は確認できるが、汚染を避けてクリアできることが未確認 |

このほか、ボスによる出現・再出現、呼出回数や実行条件が未確定なものを保留する。上の件数は群の重複があるため合算しない。全件の `holdReasons`、`unresolvedReasons` と原データの位置は監査JSONに保存している。

パラメータ上の参照が見つかったことだけでは、実行されること・任意であること・実行回数の証明にはならない。参照が見つからない256分岐も未使用とはみなさない。Prefabの既定値や環境側の処理から呼ばれる可能性がある。

## 再現と検証

元データの同一revisionのキャッシュとV2/V3アーカイブを用意して、次を実行する。

```sh
node scripts/auditEnemyBranchMechanisms.mjs
```

入力のパスとSHA-256を監査JSONに保存する。`--source`、`--archive`、`--baseline`、`--buff-template`、`--output` で入力・出力を明示できる。入力の元データ版が一致しない場合は監査を停止する。

監査スクリプト自体は集計を変更しない。実際の判定は共通の [enemySpawnConditions](../../scripts/lib/enemySpawnConditions.mjs) を通じて、マップ詳細・ヒストグラム・章別統計に反映する。テストは原データのfixture、未知の設定の反例、通常波の維持、必須出現の加算、アーカイブ保存・読み戻しまで確認する。

上記は未完了だったV3の対応範囲を拡張した時点の記録。V3の監査JSONとアーカイブは、その時点の結果として保存する。

## V4：確定出現分の下限集計

V4は、V3でマップ全体を保留していた場合にも、通常スケジュールの確定出現と確認済みの必須分岐を採用する。未知の分岐・抽選・条件付き出現の体数は加算しない。これは「出現しないと確認済み」ではなく「未算入」であり、未解析の条件と元の保留理由を残す。

ここでいう下限は、この集計規約によって読み取れた出現数を意味する。全プレイ経路を調べた実現可能な最小登場数ではない。下限の出現数から計算した割合や平均値も、実際の割合・平均値の下限を保証するものではない。

| 集計対象 | V3 | V4 | V4で下限集計に追加 |
| --- | ---: | ---: | ---: |
| 全体 | 1,454 | 1,735 | 281 |
| メインテーマ | 439 | 484 | 45 |
| イベント | 980 | 1,216 | 236 |
| 物資調達・SoC | 35 | 35 | 0 |

V3で保留されていた分岐279マップのうち262マップを追加した。ほかの出現条件による保留からも19マップを追加した。対象外は409マップ、データ未取得は197マップ。物語環境と「その他」は引き続き除外する。元データのrevisionはV3と同じで、V1〜V3の固定アーカイブは変更しない。

分岐の残り17マップは、採用できる正の敵出現数がないため保留を維持する。取得済みで集計範囲内の保留は全体で43マップ。未知の置き換え・難易度設定、不正な構造・体数なども保留し、通常波が一部読めることだけで救済しない。空配列が `{}` として保存されている箇所は、空であることと周囲の構造を確認できる場合に限り扱う。

共通判定は [enemySpawnAggregation.mjs](../../scripts/lib/enemySpawnAggregation.mjs)。マップ一覧には `spawnAggregation`、ヒストグラムには `summary.lowerBoundMapCount` と `diagnostics.lowerBoundLevels` を保存する。旧来の完全集計の成否を示す `status` / `spawnCount` は維持し、下限集計の対象かどうかと区別する。版の読み込み時には、マップID・採用体数・未解決理由が両データで一致することを検証する。

下限集計は `generateLocalGameData` の既定値で、個別の生成関数は旧動作を保つ。個別に使う場合は `spawnAggregationMode: 'lower-bound'` を明示する。固定データと差分は [V4アーカイブ](../../public/data/enemy-aggregation/v4.json.gz) および [版一覧](../../public/data/enemy-aggregation/index.json) に保存し、実データの再読込とV3との差分を [enemyLowerBoundArchive.test.ts](../../tests/enemyLowerBoundArchive.test.ts) で確認する。
