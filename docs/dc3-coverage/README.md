# DC3対応状況の履歴

DC3の対応状況を、全スキルの判定結果として保存する。版ごとの対応範囲と、追加・変更・削除されたスキルを比較するための履歴であり、過去の計算器を実行する機能ではない。

## 保存する情報

`public/data/dc3-coverage/` に次を保存する。

- `index.json`: 公開する版、件数、生成元、各版ファイルのSHA-256。
- `v1.json`、`v2.json`など: その版の全スキル、対応判定、スキル・素質・特性の内訳、計算範囲、対応条件、未対応理由。

未対応スキルも含め、保存時点の母集団をそのまま保持する。過去版の表示に現在のスキル一覧を結合しない。比較のキーはオペレーターIDとスキル番号で、未対応から対応への変化は「変更」とする。「追加」は母集団に新しく加わったスキルを指す。

`source` はコードのコミット、未コミット変更の有無、ソースの指紋、ゲームデータのリビジョンと指紋、再集計した版かどうかを記録する。コードの指紋は `src/lib`、`src/data`、`src/types` のファイルパスと内容のSHA-256から作り、出力した履歴ファイル自身は含めない。ゲームデータの指紋は集計に使った5テーブルのファイルパスと内容のSHA-256から作る。

## 最初の2版

| 版 | 内容 |
| --- | --- |
| v1 拡張前（再集計） | 拡張前のコミットのコードを、今回と同じゲームデータで再集計した結果。`reconstructed: true`。当時保存した集計結果ではない。 |
| v2 対応拡張 | 今回の拡張後のコードで集計した結果。保存時点では変更が未コミットのため `codeDirty: true`。 |

両版は同じ915スキルを対象とする。ゲームデータの更新による差を混ぜず、今回の対応範囲の変更を比較できる。保存後のコードが変わっても、これらの結果は更新しない。

## v3 対応一括拡張

v2と同じ915スキルを母集団に、37オペレーターの54スキルを利用可能にした。未対応から44スキル（対応43・条件付き1）、保留から10スキルを追加した。新規登録は27オペレーター・62スキルで、そのうち18スキルは具体的な未解決理由を付けて保留としている。

| 状態 | v2 | v3 | 差分 |
| --- | ---: | ---: | ---: |
| 対応 | 286 | 339 | +53 |
| 条件付き | 10 | 11 | +1 |
| 保留 | 77 | 85 | +8 |
| 未対応 | 542 | 480 | −62 |

攻撃力・攻撃速度・連撃・対象数・HP条件などの既存処理を再利用し、スキルによる防御力／術耐性低下、軽減後の与ダメージ倍率、攻撃力参照の継続ダメージを共通処理へ追加した。決闘者のSP自然回復制限も構造化し、発動中の直接ダメージとは区別している。

「対応」は登録された1攻撃・発動1回・固定状態でのDPSなどの計算範囲を表す。発動時・通常攻撃・終了時を分けて評価するスキルは、全段階を合算した総ダメージを返さない。ホルハイヤS2は連撃途中の浮遊を再現しないため、浮遊が有効でない対象に限定した条件付き対応としている。付与・失効、途中撃破、召喚ユニット、移動、SP回復を含む全期間の再現を意味しない。

保存時点の変更は未コミットのため、v3の生成元にも `codeDirty: true` とコードの指紋を記録する。

## 新しい版を保存する

開発サーバーで準備した `.cache/local-game-data` の完全なローカルスナップショットが必要。保存コマンドはネットワークからデータを取得せず、ローカルデータの全ファイルのサイズとSHA-256を確認してから使用する。集計中にソースが変わった場合は保存を中止する。

```sh
npm run archive:dc3-coverage -- --label "v3 対応スキル追加"
```

版番号は未使用の次の番号を自動採番する。ラベルは表示用で、版番号を指定する引数ではない。最新版との比較で対応結果に変更がなければ `unchanged` となり、ファイルを追加しない。生成日時、コミットや指紋、説明の配列順だけの変化でも版を増やさない。

過去のコードを使う場合は、コミットを明示する。

```sh
npm run archive:dc3-coverage -- --label "過去コードの再集計" --revision <commit>
```

指定したコミットのソースを `.cache/dc3-coverage/reconstructed-.../` に書き出し、現在の検証済みゲームデータで集計する。チェックアウトや作業ツリーの切り替えは行わない。計算条件の昇進段階も指定コミット側の定義を使う。古いコードが現在のデータや実行環境に対応していない場合は失敗するため、結果を推測して補完しない。

## 不変性と失敗時の扱い

- 版ファイルは新規作成のみで、既存ファイルを上書きしない。公開済みの版を再生成して置き換えない。
- 保存前に、公開済みの全版のSHA-256、スキル件数、状態別件数、メタデータを再検証する。不一致があれば追加を中止する。
- 版ファイルを保存・再検証した後で、一時ファイルから `index.json` を原子的に置き換える。読者は完成した版だけを参照する。
- 中断によって索引に未登録の版ファイルが残った場合も上書きせず、その番号を飛ばす。公開済みの索引を手編集して残骸へ接続しない。
- `.cache/dc3-coverage/archive.lock` で同時保存を防ぐ。異常終了後に残った場合は、記録されたPIDの処理が終了していることと保存先の状態を確認してから復旧する。コマンドは他の処理のロックを自動削除しない。

保存したJSONと索引をコード変更と一緒にコミットする。以後の修正は新しい版として記録する。

## 検証

```sh
node --experimental-strip-types --test tests/dc3CoverageArchive.test.mjs
```

全母集団の保存、過去版の不変性、重複版の抑止、ハッシュ・件数不整合の拒否、同時保存の拒否、中断後の採番、ソースの指紋、作業ツリーを変更しない過去コード抽出を確認する。
