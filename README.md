# Arknights Skill Analyzer

アークナイツのゲームデータからスキル効果タイプを自動分類し、判定根拠・信頼度・例外を確認するための分析ツールです。

## 技術構成

- Vite
- React
- TypeScript
- ArknightsAssets/ArknightsGamedata の JP データ
- GitHub Pages

## 開発

```bash
npm install
npm run dev
```

開発サーバーの起動時に、JPゲームデータの更新を自動確認します。更新があれば、オペレーター・スキル・MOD・所属情報・敵の基本情報を取得し、敵の登場ステージ数・出現数・マップ・章別統計も同じ版から再生成します。取得と整合性検査が完了した27ファイルをまとめて切り替え、開いている画面を再読み込みします。画面側も取得元の版を固定するため、更新途中に異なる版のOP・スキル・MODを組み合わせません。

元データと生成結果は `.cache/local-game-data/` に保存します。元データと集計処理に変更がない場合は保存済みの結果を使います。通信・検査に失敗した場合は、前回成功したデータで起動します。初回の取得中はサーバーを待たせず、集計・マップは同梱データ、OPなどの基本情報は従来の外部取得を使用します。キャッシュ作成後は基本情報も外部通信なしで表示できます。元リポジトリに未収録のステージは既存の欠損表示を維持します。

敵の統計分析・集計マップ確認では、`public/data/enemy-aggregation/` の固定集計版を使用します。マップの採否・敵の出現数・登場マップ数・敵ステータスを同じ元データ版で保存し、両ページの「集計データ」で切り替えられます。選択はページ間で共有し、URLの `aggregationVersion=v2` でも指定できます。保存画像名と保存用ヒストグラムにも版を記録します。版の取得に失敗した場合は別の版へ置き換えません。

自動更新の検証完了後は、集計内容・元データ・判定規則に変更があれば新しい `vN.json.gz` と履歴を追加します。このディレクトリはGit管理対象で、既存の版を上書き・削除しません（従来の `public/data/maps/` 等は自動更新で上書きしません）。`index.json` に元データrevision、規則名、生成コードのハッシュ、圧縮前後のファイル検証値、前版との差分を保存します。本番ビルドにも旧版を含めて配布します。

初期履歴は同一元データ `60e3aaf434919fbca931024a59d51088e810a9d3` の v1（従来判定、1,309マップ）と v2（出現グループ初期無効、1,384マップ）です。v2は対象難易度に適用される有効化設定で出現を判定します。不明な追加条件・競合・分岐・ランダム出現は引き続き保留し、物語環境・その他の除外方針も維持します。

検証済みのローカルスナップショットを手動で保存する場合は `npm run archive:enemy-aggregation` を実行します。再生成日時だけの違いでは版を追加しません。過去の生成処理の結果を保存する場合は `-- --rule-version <当時の規則名> --description <変更内容>` を明示し、当時のスナップショットを使用してください。起動時の自動更新停止は、集計版の自動追加も停止します。

v6では、同じ元データ版の協心競技（IG）の出現処理を共通化しています。抽選グループ・パックを持たない出現の `weight` は抽選確率として扱いません。抽選グループでは、各候補パックの出現数を敵ID別に比較し、全候補に共通する下限だけを加算します。これは最小の合計体数を持つパックを選ぶ処理ではなく、各敵の出現数の下限です。候補が同じパックを共有する場合、結果依存の `bonus` / `bonus_f`、未対応の条件・置換は推測しません。民間人などの役割判定も既存の共通処理を使用します。

IGの特殊WAVEは通常WAVEと分け、要塞ディフェンスでは初回WAVEのうち時間切れ前の出現を確認できる範囲を下限として集計します。後続WAVEを一括で合算しません。サッカーの試合結果に応じたWAVE選択・敵置換、ローイングの区間抽選・区間離脱による出現予約の打ち切りは未対応です。解析根拠のゲーム本体ハッシュ・RVAと適用範囲は `scripts/lib/randomSpawnPolicy.mjs` / `cooperateWavePolicy.mjs` に記録し、ゲーム本体を実行・同梱せず、生成時はJSONのみで判定します。v1〜v5の固定結果は変更しません。

v7では、検証済みのIG抽選について候補の重み比から理論期待出現数を計算します。互いに排他的な候補を重み付けし、不明な候補の確率を既知の候補へ振り替えません。既知の出現だけを計上するため、各プレイで保証される体数とは区別して「期待出現数（下限）」と表示します。既に対象の抽選マップにも同じ計算法を適用し、出現数の分布に小数の重みを使用します。整数の保証下限と期待値の版情報・マップ診断を分け、v1〜v6の保存結果は維持します。

v8では、敵統計の登場マップ数・出現数を通常の戦闘マップに絞ります。公式の `activity_table.zoneToActivity` と `basicInfo.type` により、協心競技・導灯の試練・鋒矢突破・堅守協定・デュエルチャンネル・再建画策・視像博物館・ヒュムノイの叡智・エイプリルフールを除外します。通常のサイドストーリー・オムニバスは維持します。特殊モードのマップ本体と解析結果は一覧に残し、統計対象外の理由を表示します。物語環境・その他の既存除外も継続し、v1〜v7の保存結果は変更しません。未知のイベント種別や分類データの欠落は通常扱いにせず、更新を停止します。

v9では、通常WAVE内の空の `actions: {}` を、出現処理を含まない区間として読み取ります。区間の待ち時間と順序を保持し、欠落・null・非空オブジェクトは引き続き未解析にします。SS-EX-5の固定出現34体を集計対象に追加し、通常・強襲で共有するlevelは従来どおり1マップとして数えます。同じ表現の保全駐在5マップも読み取りに対応しますが、統計の対象外を維持します。v1〜v8の保存結果は変更しません。

更新状況はサーバーのログに表示します。一時的に更新確認を止める場合は、環境変数 `ARKNIGHTS_AUTO_UPDATE=0` を設定して起動してください。この場合も、保存済みの集計データは利用します。自動更新はローカル開発サーバーだけに適用され、`build`・`preview`・公開サイトには影響しません。

ビルド確認:

```bash
npm run build
```

敵の登場ステージ数データを更新:

```bash
npm run generate:enemy-stages
```

`stage_table.json` の戦闘ステージを `levelId` 単位で重複除去し、各Level JSONから `public/data/enemy-stage-appearances.json` を生成します。取得できなかったLevelと未対応の敵IDは生成物の診断欄に残ります。

## 現在の機能

- GGのDAT解析（`#/analysis/code`、既存のリンクを維持）
  - このPCの開発用プレビューでは、`C:/YostarGames/Arknights_JP/Arknights_Data/il2cpp_data/Metadata/global-metadata.dat` をページ表示時に自動読込。失敗時は手動選択でき、手動選択・中止・解除・ページ離脱は進行中の自動読込を取り消す。公開ビルドでは自動読込を行わず、ゲームファイルを配布物へ含めない
  - DATを自動読込した後は、同じ固定インストール先の `C:/YostarGames/Arknights_JP/GameAssembly.dll`（256 MB以下）も自動読込し、処理一覧と最初の処理の命令・フロー図を生成。DLLの手動選択・中止・解除・DAT変更・ページ離脱で取得を取り消す。手動で選んだDATにはDLLを自動で組み合わせず、対応するDLLの選択を待つ
  - `global-metadata.dat`（IL2CPP版29）を選ぶとGG関連の情報を自動抽出。名前・クラスと型・処理・データ項目を一つのテーブルにまとめ、種類・所属・定義と名前の保存位置を表示
  - ファイルはブラウザー内のWorkerで読み取り、抽出後にWorkerを終了。外部へ送信せず、抽出結果はファイルを解除するかページを離れると破棄
  - GG関連の中で名前・所属を検索し、DAT内の保存位置や引数名を出典付きでコピー
  - 「表をコピー」で現在の絞り込み結果をタブ区切りで出力（全ページ、区分・出典付き）。「全件の詳細を保存」は検索条件に影響されず抽出全体を保存
  - GG名に直接一致するクラスのメンバーを含め、その他の所属先は参考情報として区別。AutoChess側の項目を明示し、共通処理・継承元・呼び出し先の網羅は行わない
  - クラスの詳細から、GG関連として抽出した処理・データ項目を所属番号で正確に絞り込む。件数も抽出範囲に合わせ、処理・項目から所属クラスへ戻れる
  - 初期表示はGG関連の全種類と参考用の所属先。種類による絞り込みにも対応。検索語が空欄ならGG関連の全件を表示し、名前が見つからないファイルは0件として扱う。Driveへの保存は手動
  - 標的切替分析の表・操作帯を再利用し、全列の罫線、固定ヘッダー・先頭列、領域内スクロールを統一。行の項目名から詳細を開き、開閉状態をページ単位で保存
  - 1ファイル128 MBまで。部分一致で大文字小文字を区別せず、200件ずつページを切り替えて全件を閲覧
  - DAT以外や未対応の形式、破損した表・参照関係を拒否。読めない名前への参照は代替表示で関係を保持
  - DAT読込後の「処理の中身を調べる」で、同じインストールのWindows x64版 `GameAssembly.dll`（256 MB以下）を選択。モジュール名・処理トークン・ポインター数と実行領域を照合し、GGの処理に対応するRVAとDLL内位置を表示。同一ゲーム版であること自体は自動保証しない
  - iced-x86 1.21.0のWASMで命令・比較・分岐・直接呼出しを表示。DLLの例外処理用範囲表の1区間を読み、分岐先・呼出し先・次区間へ移動できる。共有アドレスの別名を保持し、終端未確認は最大256バイト、既知区間は最大64 KB・5000命令で制限
  - パネル5の「処理の流れを見る」で、DLLの区間境界・分岐・継続からフロー図を自動生成。箱から命令を選択でき、途中への合流は破線と正確なRVAで表示。図内の選択は読み取り済みの命令を再利用し、移動先の命令を強調。区間内の流れの表と解析済みの説明も折りたたんで確認できる
  - フロー図は直接呼出しを展開せず、別の名前付き処理・範囲境界不明・先頭から256 KB・32区間・16000命令で探索を制限。間接移動と範囲外への移動を明示。区間はC#メソッドの境界を保証するものではなく、条件の充足やゲーム上の意味は推定しない。AI・外部API・追加ライブラリは使用しない
  - 間接呼出し・仮想呼出し・実行時差し替え・ゲーム仕様の自動判定は対象外。コピーにはDAT/DLLのSHA-256、RVA、DLL内位置、命令と制約を含む。DLLの実行や外部送信は行わず、解除・DAT変更・ページ離脱でWorkerを破棄
  - 逆アセンブル用WASMは初めてDLLを選んだ時に読み込む。`scripts/icedBrowserPlugin.mjs` が固定版iced-x86のNode用ローダーのみをブラウザー向けに変換し、依存パッケージ自体は編集しない
  - 参照仕様: [Il2CppDumperのメタデータとモジュール定義](https://github.com/Perfare/Il2CppDumper/tree/master/Il2CppDumper/Il2Cpp)、[Microsoft PE/COFF](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)、[iced-x86](https://github.com/icedland/iced)。iced-x86のMITライセンスは `public/licenses/iced-x86.txt` に同梱
  - 名前と定義レコードの保存位置を区別。いずれも実行アドレスではない。DAT一覧ではネイティブ型情報の完全な解決や処理本体・ゲーム内の挙動の判定は対象外
- オペレーターデータベース
  - 頭文字・職業・レアリティ・文字列による絞り込み
  - 最終昇進・最大レベル・信頼度100時点の基本ステータス一覧
  - 潜在能力・特性・素質・全スキル・標準モジュールの詳細表示
- 全スキルのテーブル一覧・検索・絞り込み・列ごとの並び替え・効果詳細モーダル
- Skill Effects（`#/skill-effects`）で、スキル説明文から効果とその内容を一覧化
  - 専用ページでオペレーターを検索し、スキル・レベルを選択して解析結果を表示
  - 選択内容をURLに保持し、再読み込み・戻る／進むでも同じ対象を表示
  - 「効果」列には、説明文の変数が参照する元データのキーを表示。参照元を特定できない場合は、解析結果JSONの効果名を表示
  - 説明文の根拠・文脈の確認、解析結果と選択レベルの元データをJSON詳細モーダルで表示・コピー
  - 説明文の変数を展開してルールに合う効果を読み取り、解析できなかった記述・値を取得できない変数を表示
  - 浮遊ユニット・ブロック・治療対象・チャージ・弾薬の数、能力値、回復・バリア、ダメージ、状態異常の時間など、明記された表現に対応
  - 加算量・変更後の値・倍率・上限・毎回の量と発生間隔を区別。条件・対象は根拠の文章と文脈に保持し、効果を無条件に自身へ適用しない
  - 数値が不明な強弱表現、解決できない変数、意味を確定できない独自効果は推測しない。固定の数字からblackboardのキーを逆引きしない
- オペレーターデータベースのスキル名から分類詳細をポップオーバー表示
- `duration` / `durationType` / 説明文による自動分類

- 手動分類の上書きと LocalStorage 保存

- ダメージ計算機（初期版）
  - オペレーターの昇進段階・レベル・信頼度、スキルレベルを反映
  - モジュールとLvを選択し、能力値補正と登録済みの特性・素質変更を反映
  - 通常攻撃と単純な攻撃系スキルの1ヒット・DPS・総ダメージ
  - 敵の防御力・術耐性と、敵ステータス別の比較表
  - ゲームデータから推定した倍率・ヒット数・攻撃間隔の手動調整

  - 終了条件・職業・レアリティ・名前などによるスキル絞り込み
  - 終了条件に応じたダメージ・DPS・スキル総ダメージの切り替え
  - 防御力と術耐性を組み合わせた最大10個の敵条件で横断比較
  - 最大スキルレベルの効果・発動情報を詳細モーダルで表示
  - 表示中の比較結果をUTF-8 CSVで出力
- 敵分析
  - 敵図鑑と敵戦闘データを敵IDで結合
  - 敵ごとの登場ステージ数を一覧・詳細・統計グラフ・度数分布表へ表示
  - 敵名・図鑑番号・能力・区分・攻撃種別による検索と絞り込み

  - サイト内で加工・算出する分類、ダメージ、統計、敵ランクの由来を明示
  - 敵の登場ステージ数スナップショットの生成日時・処理状況を表示

## 分類について

現在の分類器はヒューリスティックです。`durationType = AMMO` などの構造化データによる高信頼ルールと、説明文による中・低信頼ルールを分けています。今後は既存の手動分類データを正解データとして照合し、ルールを改善する想定です。
